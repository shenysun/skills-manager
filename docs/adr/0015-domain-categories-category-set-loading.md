# ADR-0015: Domain categories and category-set loading

Skills are loaded wholesale from runtime directories — there is no per-skill switch in any agent, so "start a session with only the frontend/finance/backend skills" has no mechanism. The registry's legacy scalar `category` (values like `experimental`) is a maturity/kind axis, already wired into `collections/` and `list --category`; reusing it for domain grouping would pollute those surfaces, and the idle `tags` field has no established semantics.

**Decision:** a **new multi-valued registry axis** `categories: []` — free-form domain strings (前端 / finance / backend …), no controlled vocabulary, orthogonal to the frozen legacy `category`. Loading by domain is a **distribute-level operation**: `categories apply <cat...>` resolves the selected agents (same selection semantics as distribute: `-a` multi-select, default detected, physical paths deduped) and rewrites their runtime directories to exactly the skills in those categories — distributing missing entries and removing non-selected **managed** entries (managed-only, with snapshots; removal is **path-strict and deliberately bypasses per-agent reference counting** — an out-of-set entry goes even if an unselected same-path family agent still references it, because the path must equal exactly the set; in-set entries fold in the union of referencing agents). Uncategorized managed skills are also removed (strict "only the selected set"); foreign entries are never touched; the manager skill is unconditionally exempt (ADR-0014 — removing it would cut off the conversation that switches categories). *(Removal semantics amended 2026-09-11, ruling on issue 08.)*

The applied set is persisted hub-side **per physical runtime path** (agents sharing a directory necessarily share the set) as the **category set (类别集)**. Apply is an explicit snapshot: later tag edits or updates never auto-push; `categories status` surfaces drift ("N skills now match the set but are undistributed") and re-running `apply` syncs. `apply --all` restores the full managed set. User-target rollback restores the runtime content **and** the category-set record together, so status/doctor never misreport. Scope is user-level only in v1; project-level and any dashboard tagging UI are deferred, and `collections/` stays on the legacy axis with no new-axis consumer.

_Avoid_: a second loading mechanism outside distribute; mixing domain tags into legacy `category` or `tags`; a controlled vocabulary; auto-push on tag/update changes; per-agent-id category sets on shared paths; named switchable "profiles" (the v1 set is a state, not a saved profile).
