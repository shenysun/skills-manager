# ADR-0019: Named presets (named category subsets)

ADR-0015 deliberately shipped the applied category set as a state, not a saved profile ("named switchable 'profiles'" sat in its _Avoid_ list as a v1 deferral). Two competitors have since validated the need: asm bundles and xingkongliang presets. Our model needs the **switch** half of that need — a named, re-appliable subset of domain categories — not the install-group half.

**Decision:** a **preset (预设)** is a named list of domain categories, stored as a top-level `presets:` map in `registry.yaml` (`{ <name>: { categories: [...] } }`, object-shaped for future fields). An independent `preset` command group manages them: `set` (replace semantics, overwrite-in-place, safe-preset-name validated — no reserved words), `list` (name + member categories + mount footprint: how many physical runtime paths carry it; omitted when zero), `remove`, and `apply`. `preset apply <name>` resolves the categories through the unchanged ADR-0015 path-level strict semantics (manager skill exempt, foreign untouched, uncategorized removed, user scope only) and stamps the applied category-set record with an optional `preset` field — the shape becomes `{ categories: string[]; preset?: string } | { all: true }`. A bare `categories apply` over a preset-stamped path clears the field (manual override of the档位); `preset remove` cascades the same clearing over every record referencing the name (categories kept, runtime untouched). Two hard-error gates protect the named object: a preset that resolves to zero managed skills, and a preset referencing a category absent from the vocabulary, both refuse at apply time (storage is unvalidated — build the preset first, tag later); bare `categories apply` semantics are untouched. Apply output ends with a resident-cost line (char-approx, ADR-0018 core reused; structured field in `--json`).

Supersedes ADR-0015's _Avoid_ clause on named switchable profiles; everything else in ADR-0015 stands. Preset visibility in v1 is `preset list` and `categories status` only — the cost surfaces (human, `--json`, `GET /api/cost`) carry no preset annotation. Deferred: category-plus-explicit-pin mixed membership, project scope, dashboard preset pill, and any remote preset catalogue (the asm online-bundle-directory form — local declarations only).

_Avoid_: the word "bundle" (npm packaging ambiguity; asm's bundles are install groups, not load switches); mixed pin membership in v1; preset annotations on the cost ledger; a second loading mechanism outside distribute; per-agent-id presets on shared paths.
