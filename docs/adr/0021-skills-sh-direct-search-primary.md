# ADR-0021: skills.sh direct search API as the primary discovery channel

ADR-0012's agent-side search had two channels: `npx skills find` (primary) and GitHub code search (fallback). Deep-dive verification of skills.sh (2026-09) confirmed a usable public search endpoint — `GET https://skills.sh/api/search?q=<kw>` returning structured JSON (`skills: [{id, skillId, name, installs, source}]`) with install counts. The npx channel works but is slow and regularly breaks on some npm setups (`Unknown command`), and it is itself a wrapper over the same registry.

**Decision:** the manager skill's search layer gains a **direct skills.sh API channel as primary** (`curl` + JSON parse, run by the agent in-session), demoting `npx skills find` to second (kept as a buffer against API drift — it rides the server-side prebuilt-snapshot path), with `gh api search/code` third. Channel discipline is unchanged: any failure — timeout, non-200, JSON parse failure, missing or empty `skills` array — means "channel unavailable", degrading silently to the next channel, with the result stating which channel served it; one query, no retries, no undocumented parameters, English keywords distilled by the agent. "No retries" is the default channel discipline scoped to channels ① and ②; channel ③ alone keeps the single rate-limit retry it inherits from the pre-existing backfill discipline (wait ~20s, retry once on 429/403) — the one sanctioned retry. The channel table is **shared** by both consumers: the provenance-backfill Step 3 and a new generic **find workflow** ("帮我找个 X skill") — candidates are verified before presentation (upstream SKILL.md `name`/`description` compared against the ask, the existing "verify before presenting" bar), shown as name + `owner/repo` + installs (an adoption signal, never a quality verdict) + skills.sh link, and installed through the unchanged source-first install machinery (git source parsed from `source`/`skillId`) behind user confirmation — the same boundary as ADR-0012 Layer 3.

Amends ADR-0012's channel list (dual → ordered three); its non-goal "skills.sh search wrapped as a CLI command" stands — the CLI gains no `find` command and no network capability beyond ADR-0020's git transport and catalog refresh. skills.sh is a double-edged upstream (shared with the desktop rival): adopting it buys the installs signal and the discovery layer, and our differentiation stays in verification discipline plus the provenance-backfill search layer.

_Avoid_: a CLI `find` command; treating `installs` as a quality verdict; presenting unverified candidates; retries beyond channel ③'s single sanctioned rate-limit retry, multi-query polling, or guessed API parameters; deleting the npx channel; a dashboard search surface.
